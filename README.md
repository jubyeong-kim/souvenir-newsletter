# 오늘의 기념품

매일 아침 **대륙이 하나씩 돌아가며**, 그날 선정된 국가에서 지금 화제인 기념품을 추려
디스코드로 발행하는 뉴스레터 에이전트입니다.

여행을 준비하는 독자가 "이번 여행에 뭘 사올까"를 정할 수 있도록, 기사 본문을 실제로 읽고
요약한 뒤 **원문에 없는 내용이 섞이지 않았는지 검수한 것만** 내보냅니다.

- 발행 예시와 설계 판단은 **[REPORT.md](REPORT.md)** 에 있습니다.
- 날짜만으로 대륙·국가가 결정되므로 같은 날 실행하면 항상 같은 국가가 나옵니다.

## 파이프라인

```
START → collect → select ─(기사 수만큼 팬아웃)→ report → verify → publish → END
        수집       선별                          취재      검수      발행
```

| 단계 | 하는 일 |
|---|---|
| **수집** | 국가별 쿼리형 소스(Tavily·YouTube)와 고정 RSS에서 후보를 모읍니다 |
| **선별** | 예선(묶음)→본선 2단계로 추리고, 한 소스가 자리를 독차지하지 못하게 상한을 겁니다 |
| **취재** | 본문을 확보해 헤드라인·요약·여행자 관점 인사이트를 씁니다 |
| **검수** | 품목명 원문 대조 → 숫자 대조 → LLM 근거·국가 판정. 비용 0인 검사부터 돌립니다 |
| **발행** | 검수를 통과한 것만 디스코드 임베드로 보냅니다 |

검수에서 떨어지면 그 건은 버리고, 목표 건수에 미달해도 **기준을 낮춰 채우지 않습니다.**
한 건도 남지 않은 날에도 안내 임베드 한 장은 보냅니다 — 아무것도 안 보내면
파이프라인이 죽은 것과 구분이 되지 않기 때문입니다.

## 폴더 구조

```
souvenir-newsletter/
├── graph.py                     파이프라인 전체. 여기에는 '구조'만 둡니다
├── run.py                       실행 진입점
├── audience.yaml                '내용'은 전부 여기 — 독자 정의, 선별 기준,
│                                대륙·국가 로테이션, 소스 목록, 임베드 색상
├── requirements.txt
├── REPORT.md                    프로젝트 보고서 (소스 채택표·선별 로직·실행 기록)
├── docs/
│   └── discord.jpg              발행 화면 캡처
├── store/
│   ├── metrics.jsonl            실행마다 한 줄. 수집→선별→취재→발행 깔때기
│   └── seen.json                이미 발행한 URL. 같은 것을 다시 보내지 않습니다
└── .github/workflows/daily.yml  매일 09:00 KST 자동 실행
```

**다른 분야로 옮기려면 `audience.yaml` 만 고칩니다.** 소스 종류(`tavily`/`youtube`/`rss`)와
국가 로테이션, 선별 기준이 전부 설정 파일에 있어서 파이썬을 열 일이 없습니다.

## 실행

```bash
pip install -r requirements.txt
```

`.env` 파일에 키를 넣습니다. 이 파일은 커밋되지 않습니다.

```
OPENAI_API_KEY=
DISCORD_WEBHOOK_URL=
TAVILY_API_KEY=
YOUTUBE_API_KEY=
```

```bash
python run.py
```

`DRY_RUN` 은 **기본값이 보내지 않음(`1`)** 입니다. 실제로 발행하려면 `DRY_RUN=0` 을 줍니다.
기본값을 이렇게 둔 이유는, 설정을 빠뜨린 채 돌렸을 때 조용히 발행되는 쪽보다
아무 일도 일어나지 않는 쪽이 안전하기 때문입니다.

## 설계 판단 — 왜 이렇게 만들었나

**왜 LangGraph의 팬아웃(`Send`)인가.**
기사마다 본문을 받아오고 LLM을 부르는데, 이건 서로 의존이 없습니다.
순서대로 돌리면 기사 수만큼 시간이 곱해집니다. 선별이 끝난 시점에
`Send` 로 기사 수만큼 워커를 펼치고, 결과는 `drafted` 에 리듀서(`operator.add`)로 합칩니다.
`verified` 에 리듀서가 없는 이유는 검수가 **늘리는 일이 아니라 줄이는 일**이기 때문입니다.

**왜 선별이 2단계(예선→본선)인가.**
후보 전부를 한 번에 넣으면 프롬프트가 길어져 뒤쪽 후보가 묻힙니다.
묶음으로 나눠 예선을 거친 뒤, 살아남은 것만 한 화면에 놓고 본선에서 비교합니다.
상대평가는 같은 화면에 있을 때만 제대로 됩니다.

**왜 상한을 프롬프트가 아니라 코드로 거는가.**
"한 소스가 자리를 독차지하지 않게 해줘"를 프롬프트로 부탁했더니 지켜지지 않았습니다.
`Counter` 로 세서 막으니 지켜집니다. **세어서 지켜야 하는 규칙은 코드로 셉니다.**

**왜 검수를 비용 순서로 놓는가.**
품목명 대조(0원) → 숫자 대조(0원) → LLM 판정(유료). 앞에서 걸리면 LLM을 부르지 않습니다.
품목명 대조는 외부 조회가 아니라 우리가 받아온 원문과의 문자열 비교라 **오탐이 없습니다.**

## 폭주·실패 방지

사이클이 없는 DAG(`collect→select→report→verify→publish`)라 무한 루프가 구조적으로 생기지 않습니다.
그 위에 상한을 겁니다.

| 장치 | 값 | 무엇을 막나 |
|---|---|---|
| 소스별 후보 상한 | 8건 | 한 소스가 후보를 독점해 상대평가가 거기서만 이뤄지는 것 |
| 팬아웃 워커 수 | 최대 `건수 + 여유분` = 8 | LLM 호출이 후보 수만큼 무제한 늘어나는 것 |
| 발행 자리 상한 | 소스당 3건 | 한 소스가 지면을 독차지하는 것 |
| HTTP 타임아웃 | 20~60초 | 응답 없는 소스에 매달리는 것 |
| Tavily 재시도 | 3회 고정 | 간헐적 빈 응답. 무한 재시도는 하지 않음 |
| LLM 입력 절단 | 본문 6,000자 | 토큰 폭증 |
| 임베드 예산 | 10장 / 5,800자 | 디스코드 전송 실패 |

**실패해도 멈추지 않습니다.** 소스 하나가 죽으면 그 소스만 건너뛰고 나머지로 진행하며,
`응답 없음` 으로 로그에 남습니다. 본문이 모자라면 그 건만 제외하고, 검수에 떨어지면
그 건만 버립니다. 목표 건수에 미달해도 **기준을 낮춰 채우지 않고** 미달인 채 발행합니다.
한 건도 남지 않으면 안내 임베드 한 장을 보냅니다 — 침묵은 파이프라인이 죽은 것과 구분되지 않습니다.

`DRY_RUN` 기본값이 "보내지 않음"인 것도 같은 이유입니다. 설정을 빠뜨린 채 돌렸을 때
조용히 발행되는 쪽보다 아무 일도 일어나지 않는 쪽이 안전합니다.

## 만든 사람이 직접 고친 부분

초안은 AI와 함께 만들었고, 아래는 **돌려보고 로그를 읽은 뒤 사람이 판단해 고친 것**입니다.
전후 수치는 [REPORT.md](REPORT.md) 의 깔때기 표에 있습니다.

| 고친 것 | 왜 | 전 → 후 |
|---|---|---|
| Tavily `search_depth=advanced` | 기본 검색은 스니펫만 줘서 본문 문턱을 못 넘었다 | 본문 확보 1/9 → 10/10 |
| 검색 창 30일 → 365일 | 30일 창은 **날짜를 주는 소스만** 골라 죽였다. Tavily는 날짜가 없어 수집시각으로 채워져 살아남는 역설 | 본문 확보 4/10 → 8/10 |
| 품목명 대조에 언어 가드 | 영어 원문 + 한글 음역(`Souk`→소우크)은 구조적으로 절대 안 맞아 **정상 요약이 전량 환각 판정** | 오탐 제거 |
| 국가 문자열 대조 제거 | 본문이 "두바이"만 쓰면 탈락시켰다. LLM 판정과 중복 | 오탐 제거 |
| 초과 선별 + 발행 직전 절단 | 정확히 5건만 뽑으면 한 건 떨어질 때마다 미달 | 발행 1 → 3건 |
| 유튜브 짧은 설명글 사전 배제 | 287자 영상이 선별 자리만 먹고 취재에서 죽었다 | 취재 3 → 5건 |
| 인사이트 필드 문구 교체 | 재사용한 코드에 이전 프로젝트의 "국내 개발팀에게 왜 중요한지"가 남아 있었다 | 도메인 정합 |
